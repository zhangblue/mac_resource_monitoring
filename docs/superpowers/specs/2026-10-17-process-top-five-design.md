# 进程资源 Top 5 设计

## 目标

在现有 CPU、内存、上传和下载四张指标卡中保留折线图，并分别增加当前资源占用最高的 5 个进程。进程排行只显示排名、进程名称和当前数值，不使用进度条，也不保存历史排行。

## 产品约束

- 保持应用为 `LSUIElement` 纯菜单栏应用，不新增常驻 Dock 图标。
- 面板宽度保持 380 pt，四张指标卡继续使用两列布局。
- 现有总量指标、折线图、动态纵轴、网格线和悬停数据行为保持不变。
- 进程排行按当前 1/3/5 秒刷新设置更新，不改变 1/5/10 分钟总量趋势窗口。
- 进程排行中单项采集失败必须隔离，不中断其他排行或现有系统指标。
- 首版继续仅支持 Apple Silicon 和 macOS 13 及以上版本。

## 界面设计

CPU、内存、上传和下载卡片在原有折线图下方增加“进程 Top 5”区域。每行依次显示排名、进程名称和当前数值：

- CPU：百分比，保留一位小数，例如 `Code Helper  14.2%`。多核进程允许超过 100%。
- 内存：格式化容量，例如 `Chrome  2.1 GB`。
- 上传、下载：格式化速率，例如 `Codex  43 KB/s`。

进程名称过长时尾部省略。同名进程同时进入 Top 5 时，在名称后追加 PID。有效进程不足 5 个时只显示现有项目，不补空行。CPU 或网络尚未建立差值基线时显示“等待下一次采样”；采集失败时显示“暂不可用”。排行区域不响应折线图的悬停交互。

## 数据模型

新增可发送且可比较的进程资源模型：

- 进程身份：PID 与进程启动时间组合，防止 PID 复用污染差值。
- 展示身份：进程名称，必要时附加 PID。
- CPU：当前采样区间内的 CPU 百分比。
- 内存：当前常驻内存字节数。
- 网络：当前采样区间内的上传和下载字节率。

`MetricSnapshot` 增加独立的进程排行读数，其中 CPU、内存、上传和下载分别拥有自己的可用、等待或失败状态。排行仅保留当前快照，每项最多 5 条，不加入 `MetricHistory`。

## CPU 与内存采集

新增 `ProcessMetricsProvider`，使用 macOS `libproc` 接口枚举进程并读取：

- 进程名称、PID 和启动时间；
- 累计用户态与内核态 CPU 时间；
- 当前常驻内存。

CPU 以同一进程身份前后两次累计 CPU 时间之差除以实际墙钟时间，得到当前百分比。结果不按逻辑核心数归一化，因此多线程进程可超过 100%。首次出现的进程、启动时间变化、累计值回退或无效时间间隔不生成 CPU 数值。内存不依赖基线，可在首次采样立即参与排序。

单个进程在枚举期间退出或因权限无法读取时跳过该进程，不让单个 PID 失败影响整个排行。

Xcode SDK 的 `libproc.h` 将这些接口标记为私有并提示未来版本可能变化。本项目不通过 App Store 分发，因此首版接受这一兼容性风险；每次发布必须用目标 macOS SDK 完成 arm64 release 构建和真机采集检查。若接口在未来系统中不可用，CPU 与内存进程排行降级为“暂不可用”，不得影响总量指标或其他采集项。

## 网络采集

网络进程排行使用 macOS 自带的 `/usr/bin/nettop`：

```text
/usr/bin/nettop -P -L 1 -x -J bytes_in,bytes_out
```

通过 `Process` 直接启动固定可执行文件和固定参数，不经过 Shell，也不拼接用户输入。解析 CSV 中的进程名称、PID、累计接收字节和累计发送字节，并通过同一进程身份的前后差值除以实际采样间隔，得到下载和上传速率。

累计值回退、进程身份变化或无效时间间隔时丢弃对应差值。速率为零的进程不进入网络 Top 5。输出缺少所需列、数字无效、退出码异常、启动失败、超时或输出超过上限时，本次网络进程排行标记为不可用。

## 采样协调与生命周期

进程采集作为独立提供器接入 `MonitoringEngine`，与 CPU、内存、总网络、磁盘和传感器并发执行。采集结果在引擎 actor 内统一提交，避免快照各部分来自不同轮次。

刷新间隔变化、系统睡眠唤醒、引擎停止或进程计数器回退时重置进程 CPU 与网络基线。应用停止、进入睡眠或没有订阅者时不启动新的 `nettop` 子进程；正在运行的子进程应被终止。`nettop` 设定有限超时和输出大小上限，防止子进程阻塞采样循环或异常输出持续占用内存。

CPU、内存和网络排行分别排序并截取前 5 项。网络上传与下载使用同一次 `nettop` 快照，避免重复启动命令。

## 失败隔离与诊断

- CPU 进程采集失败：CPU 排行显示暂不可用，内存和网络排行继续更新。
- 内存进程采集失败：内存排行显示暂不可用，CPU 和网络排行继续更新。
- `nettop` 失败：上传和下载排行显示暂不可用，CPU、内存及现有总网络速率继续更新。
- 单个进程读取失败：跳过该进程，不把整个分类标记为失败。
- 所有失败通过独立的进程排行诊断组件记录，不改变现有五类采集器的诊断结果。

## 测试

新增或扩展测试覆盖：

- CPU 累计时间差值、首次基线、多核百分比、PID 复用和计数器回退。
- 内存排序、同名进程、进程中途退出、无权限进程和 Top 5 截断。
- `nettop` CSV 列解析、包含空格的名称、上传/下载差值、零流量过滤、无效数字、格式错误、异常退出、超时和输出上限。
- 睡眠唤醒、刷新间隔变化和引擎停止后的基线及子进程生命周期。
- CPU、内存、上传和下载排行各自失败时的隔离行为。
- UI 排序、数值格式、长名称截断、同名 PID 区分、等待和失败状态。
- 现有折线图坐标、网格线、悬停和历史裁剪回归测试继续通过。

完成前运行：

```bash
swift test
swift build -c release --arch arm64
```

## 不在本次范围内

- 不保存或绘制单个进程的历史趋势。
- 不允许用户结束进程、搜索、固定或排除进程。
- 不引入 Network Extension、系统扩展、管理员权限或新的登录项行为。
- 不修改菜单栏文字，不在菜单栏直接显示进程信息。
- 不增加磁盘读写速率或磁盘进程排行。
